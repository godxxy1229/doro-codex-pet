## 2. 최종 SVG 사양

| 항목 | 내용 |
|---|---|
| 캔버스 | `viewBox="0 0 800 800"`, 800×800, 투명 배경 |
| 좌표 | `02_reference/doro_source_800.png`와 같은 좌표·구도라서 겹치면 그대로 맞음 |
| 사용 요소 | `path`, `ellipse`, `rect`, `linearGradient`, `radialGradient`만 사용 |
| 쓰지 않은 것 | 필터(블러), 마스크, clipPath, 외부 이미지·폰트, CSS(본 파일 기준) → 대부분의 편집·모션 툴과 호환 |
| 렌더 검증 | Chromium과 CairoSVG의 렌더 결과가 같음 (평균 픽셀 차 0.3/255) |
| 정확도 | 원본 선의 99.8%가 3.5px 이내로 일치. 선 주변을 뺀 채색 평균 차는 RGB 합 1.4 |
| 메타데이터 | 주요 그룹에 한글 주석과 `data-pivot="x y"`(회전·스케일 기준점) 속성 포함 |

## 3. 레이어 구조 (위에 적힌 것부터 먼저 그려짐 = 아래 레이어)

```
doro                      도로 전체
├─ body-group             몸통 + 다리
│  ├─ leg-back            오른쪽 뒷다리
│  ├─ leg-front-right     앞다리 (가운데)
│  ├─ leg-front-left      앞다리 (왼쪽)
│  └─ body                몸통 (다리 윗부분을 덮음)
│     ├─ body-fill
│     ├─ body-lines       belly-left / belly-right / body-back
│     └─ leg-creases      다리와 몸통이 만나는 짧은 선
└─ head                   머리 전체
   ├─ ribbon-tails        흰 리본 꼬리 (똥머리·보라 리본 뒤)
   ├─ hair-back           뒷머리 / 똥머리 (+ rose-band: 장미 아래 진분홍 띠)
   ├─ face                얼굴 (face-skin, blush-left, blush-right)
   ├─ eyes                eye-left / eye-right (홍채·하이라이트·테두리)
   ├─ mouth               입
   ├─ bangs               앞머리 (+ 가르마 음영, 하이라이트 3개, bangs-strands)
   ├─ lashes              lash-left (꼬리 포함) / lash-right
   ├─ hair-side-left      왼쪽 옆머리 (+ 음영, 하이라이트)
   ├─ hair-side-right     오른쪽 옆머리 (+ 하이라이트)
   ├─ rose                장미 장식 (rose-core 포함)
   └─ bow                 보라 리본
```

레이어 순서를 이렇게 둔 이유:

- 다리는 몸통 아래에 있고, 다리 윗부분은 몸통 안쪽까지 흰색으로 넉넉히 채워 두었습니다. 그래서 다리를 돌려도 이음새에 틈이 생기지 않습니다.
- 몸통의 흰 면은 머리 밑까지 이어져 있어서, 머리를 기울여도 목 부분이 비지 않습니다.
- 눈은 앞머리 아래, 속눈썹은 앞머리 위에 있습니다. 원본에서 앞머리가 홍채 위쪽을 가리기 때문이고, 같은 이유로 속눈썹을 눈 그룹과 분리했습니다.
- 앞머리 면은 옆머리 아래쪽까지 이어져 있습니다. 옆머리를 살짝 흔들어도 빈틈이 보이지 않게 하기 위해서입니다.

## 7. 모션 작업 가이드

- **기본 방식:** 각 그룹을 '4. 기준점' 표의 좌표를 중심으로 회전하거나 스케일합니다.
  - CSS로 작업한다면 `transform-box: view-box;`를 쓰고 `transform-origin: Xpx Ypx;`에 기준점을 넣습니다 (`motion_style.css` 참고).
- **눈 깜빡임:** `eye-left` / `eye-right`를 `scaleY(0.08)` 정도로 줄이면서, `lash-left`는 `translateY(32px)`, `lash-right`는 `translateY(42px)`만큼 내립니다.
  - 감은 눈을 더 예쁘게 하려면 감은 눈 모양(곡선 하나)을 따로 그려 교체하는 방식을 추천합니다.
- **검증된 범위:** 다리 ±7°, 고개 ±2.5°, 옆머리 ±1.2°, 몸통 squash 약 4%. 이 범위에서는 틈이나 이음새가 보이지 않는 것을 파란 배경 위에서 확인했습니다.
  - 이보다 크게 움직이면 이음새가 보일 수 있습니다.
- **`doro_motion_test.svg`:** 위 동작들을 반복 재생하는 예시입니다. 브라우저에서 열면 바로 움직입니다.
  - 통통 튀기 1.2초, 고개 갸웃 2.4초, 깜빡임 3.6초 주기, 걸음 0.6초.
- **툴 호환 메모:**
  - 그라디언트(선형·방사형)와 반투명 도형만 쓰고 필터는 쓰지 않아서, 다른 툴로 옮겨도 모양이 달라질 여지가 적습니다.
  - 렌더 확인은 Chromium과 CairoSVG에서만 했습니다. Figma, Illustrator, Lottie 변환기에서는 직접 검증하지 않았으니, 쓰기 전에 한 번 열어서 확인해 주세요.
  - After Effects는 SVG를 직접 가져오는 기능이 제한적입니다. Illustrator에서 AI로 저장한 뒤 가져오는 방법을 권장합니다.

## 8. 다시 만들기 / 수정하기 (03_source)

### 준비

```bash
pip install -r requirements.txt          # numpy, scipy, scikit-image, pillow, (선택) cairosvg
# (선택) Chromium 렌더: npm i playwright
```

### 전체 재생성

```bash
cd 03_source
./run_all.sh
# → out/doro.svg, out/doro_motion_test.svg, out/doro_preview.png
#   out/compare_side.png, out/compare_overlay.png + 정확도 리포트
```

새로 만든 폴더에서 다시 돌려 보면 `01_deliverables/doro.svg`와 **바이트 단위로 똑같은** 결과가 나옵니다.

### 동작 원리

1. **`step0_trace_lowres.py`** *(선택)*: 225px 원본에서 선의 중심선을 뽑아 108개의 가지로 나누고, `data/branches.json`에 저장합니다.
   - 같은 환경에서는 결과가 똑같이 나오는 것을 확인했습니다.
   - 다만 라이브러리 버전이 바뀌면 가지 번호가 달라질 수 있으니, 보통은 이미 들어 있는 파일을 그대로 쓰세요.
2. **`step1_prepare_hires.py`**: 800px 원본을 흰 배경에 합성하고, 선 중심과 두께를 뽑습니다.
3. **`build_svg.py`**: 부위마다 "어떤 가지를 어떤 순서로 이을지"를 정의합니다.
   - `fitting.py`가 이 가지들을 800px 좌표로 옮긴 뒤 800px 중심선에 정확히 붙이고, 부드러운 베지어 곡선으로 바꿉니다.
   - 홍조, 머리카락·장미 음영, 하이라이트는 `regions.py`가 원본 색에서 영역을 찾아 윤곽이나 타원으로 만듭니다.
4. **`make_motion_test.py`**: 완성된 SVG에 `motion_style.css`를 넣어 모션 테스트 파일을 만듭니다.

### `build_svg.py`에서 자주 고칠 곳

| 고칠 것 | 위치 |
|---|---|
| 색 | 맨 위 `C = dict(...)`, 아래쪽 `defs` |
| 선 두께 | `W_BODY`, `W_HAIR`, `W_DETAIL`, 각 `stroke(..., 두께)` 호출 |
| 기준점 | `PIVOTS` |
| 레이어 주석 | `NOTES` |
| 도형 경로 | 각 `P([...])`, `stroke('', [...])` 호출의 토큰 목록 |

토큰 목록은 세 종류입니다:

- `73`처럼 숫자 하나 → 가지 번호입니다. 번호는 `data/branch_id_map.png`에서 확인할 수 있습니다.
- `'16:61.2,174.8:79.5,178.5'` → 16번 가지 중에서 두 좌표 사이 구간만 쓴다는 뜻입니다.
- `(x, y)` 좌표 → 가려지는 부분을 지나가는 점입니다. 225px 기준 좌표로 쓰면 자동으로 800px로 바뀝니다. 800px 좌표를 그대로 쓰려면 `(x, y, 'n')`처럼 씁니다.

SVG를 Illustrator나 Figma에서 직접 고치면, 그때부터는 스크립트 결과와 내용이 달라집니다. 어느 쪽을 기준본으로 삼을지 미리 정해 두는 것을 권장합니다.

## 9. 작업 이력

**v1 — 225px 원본 기반**
- 원본 선의 중심을 따서 벡터로 만들고, 부위별 레이어와 기준점을 넣었습니다.
- 음영은 그라디언트로 단순화했습니다.

**v2 — 800px 원본 기반 (최종)**
- 피드백 반영
  - **홍조 위치:** 원본의 홍조 영역을 그대로 따왔습니다. 왼쪽은 눈 아래부터 볼 전체를 덮는 큰 영역, 오른쪽은 턱 쪽 옆머리 옆의 띠입니다.
  - **왼쪽 속눈썹(꼬리)이 날카로움:** 끝이 가늘어지던 처리를 없애고, 원본처럼 뭉툭한 짧은 막대로 바꿨습니다.
- 전체 보정
  - 모든 선을 800px 중심선에 맞춰 다시 붙였고, 선 두께를 원본에서 측정해 맞췄습니다.
  - 홍채의 색 경계 위치와 하이라이트 모양을 원본에 맞췄습니다.
  - 음영을 원본처럼 셀 음영으로 바꿨습니다: 가르마 음영 2단, 장미 아래 진분홍 띠, 하이라이트 5곳.
  - 속눈썹을 원본 두께로 굵혀서, 홍채 테두리와 속눈썹 사이의 틈을 없앴습니다.
  - 모든 색을 원본에서 다시 측정했습니다.

## 10. 알려진 한계 / 후속 과제

- 원본의 에어브러시 질감은 셀 음영(단색 영역 + 부드러운 하이라이트)으로 단순화했습니다.
- 원본 왼쪽 아래에서 다리 선이 머리카락 속으로 살짝 들어가던 짧은 선은 정리 차원에서 뺐습니다.
- 홍조와 음영 영역은 원본 색에서 자동으로 뽑은 윤곽이라, 손으로 그린 도형보다 점(노드)이 조금 많습니다.
- 앞머리 가닥 끝처럼 끝이 가늘어지는 선은 채움 도형이라 `stroke-width`로 조절할 수 없습니다.
- 깜빡임은 단순히 세로로 줄이는 방식입니다. 감은 눈, 다른 입 모양 같은 표정 바리에이션은 별도 작업이 필요합니다.
